# 競輪予想AI（設計書版）

設計書「競輪予想AI 設計書」のとおりに作った予想AIです。**Google Colab** で動かします。
**お金は一切使いません**（すべて仮想購入で回収率を記録）。

> ⚠️ 競輪の払戻率は約75%です。適当に買うと回収率は75%前後になります。
> このツールの役目は、自分の予想方法やAIがそれを超えられるかを、**運のブレも含めて正直に測ること**です。

---

## 使い方（Colab）

1. GitHub で `keirin_ai/keirin_colab.ipynb` を開き、「Open in Colab」（または Colab の「ファイル → ノートブックを開く → GitHub」）で開く
2. 上のセルから順に ▶ を押す
   - 1: Google ドライブをつなぐ（データと Excel の保存先）
   - 2: プログラムを取ってくる
   - 3: **架空データでお試し**（約4000レース、1分ほど）
   - 4: 本物のデータで検証（データが用意できてから）

リポジトリが非公開でうまく取れないときは、ノートブックの説明どおり ZIP をドライブに置く方法を使ってください。

## 設計書との対応

### 予想に使う列（`keirin/features.py`）
すべて「予想するレースより**前**」の情報だけで計算します（リーク防止。自動テストで確認済み）。

| 方法 | 列 | 計算 |
|---|---|---|
| 1 位置の適性 | 自力度 | 過去の決まり手の（逃げ＋捲り）÷（逃げ＋捲り＋差し＋マーク） |
| | 決まり手の合計回数 | 自力度の当てになり具合 |
| | 今回の位置 | 先頭・番手・3番手・単騎 |
| | 位置の適性 | 先頭なら自力度、番手なら 1−自力度 |
| 2 強いライン | ラインの力量差 | ライン先頭・番手の弱い方の強さ − ほかの選手の最高の強さ（強さ = −直近の大会の平均着順） |
| | ほかのラインの先行選手の数 | 自力度 0.6 以上の選手の数 |
| 3 強さ | 直近の大会の着順 | 今大会のここまでの平均着順。初日は前大会の平均着順 |
| | どちらの大会か | 今大会=1、前大会=0 |
| | 前大会からの日数 | |
| 4 調子 | 3か月の勝率・連対率・複勝率、出走数 | 直近90日 |
| | 調子の上向き度 | 直近4走の複勝率 − 3か月の複勝率 |
| 5 格 | 今回の格 | レースの格（1〜6）＋大会グレード補正（GP1.0〜F2 0） |
| | 普段の格 / 格の差 / メンバー内の格の差 | 過去のレースの格の平均から |
| | レースのクラス | S級・A級・A級チャレンジ |
| | 準決勝の着順 | 同じ大会で準決勝を走っていればその着順 |

- **使わない**: 競走得点・脚質・級班（比較用の「LightGBM＋競走得点」だけ競走得点を使う）
- **対象外**: ガールズケイリン
- 大会は「同じ場で日付が連続している開催」を自動でひとまとまりにしています
- レース名 → 格 は `keirin/race_grade.py` の決まりで自動判定。判定できない名前は Excel の「格が不明なレース名」に出るので、`race_names.csv`（列: `race_name,kaku`）に書き足します

### 答えにあたる列
1着か / 3着以内か / ライン先頭・番手の2人がそろって2着以内か → LightGBM でそれぞれ学習します。
1着確率はレース内で合計100%になるように直してから、2車複・2車単・3連複の確率（ハービル式）に変換します。

### 検証（`python -m keirin evaluate`）
- レースを**時間で**分け、古い約78%で学習、新しい約22%で試す（4500レースなら約3500／1000）
- 比べる相手: **人気順**（オッズから逆算）/ **手作り7:3**（強さ7・調子3、AIなし）/ **LightGBM** / **LightGBM＋競走得点**
- 評価の順番: 【1】的中率（1位予想の1着率・3着以内率など）→【2】回収率（仮想購入、95%区間つき）
- 仮の数値（自力度0.6、3か月、直近4走など）は `config.toml` の `[features]` で変えられます

## データについて（今いちばん足りないもの）

まだ本物のデータがありません。必要なのは、1レースごとの次の情報です。

| ファイル | 中身 | 必須 |
|---|---|---|
| races | 日付・場・R・**大会グレード**・**レース名**・**クラス**・発走時刻 | ✅ |
| entries | 車番・選手ID・**並び（ライン番号・位置・人数）**・着順・**決まり手**・欠車 | ✅ |
| payouts | 2車複・2車単・3連複の払戻金 | 回収率に必要 |
| odds | 締切前オッズ | 人気順・期待値買いに必要 |

形は `templates/` の見本と同じです。ドライブの `keirin_ai_data/inbox` に入れて `import-csv` で取り込みます。
サイトから自動で集める部品（`keirin/sources/`）は、取得元のサイトが決まってから追加します。

## 初心者が見落としがちな落とし穴

1. **架空データの数字で判断しない**: デモは動作確認用です。架空の世界の作り方次第で結果はいくらでも変わります。
2. **設定をいじって一番良い結果を選ばない**: 検証期間に合わせ込んだだけになります。設定を決めてから検証してください。
3. **1000レースの回収率はブレが大きい**: 高配当1、2本で何十%も変わります。Excel の「判定」が △ のうちは運の範囲です。
4. **確定オッズで判断しない**: `--allow-final-odds` は締切前オッズが無いときの参考値です。結果は甘く出ます。
5. **サイトの利用規約を確認する**: 自動取得を禁止しているサイトは使わないでください。

## コマンド一覧

```
python -m keirin demo          架空データで一通り試す
python -m keirin import-csv    inbox のCSVを取り込む
python -m keirin evaluate      時間で分けて検証 → Excel（--test-frac 0.22, --allow-final-odds）
python -m keirin fetch --from YYYY-MM-DD --to YYYY-MM-DD   取得元から過去分を取り込む（取得部品ができてから）
python -m keirin daily         本番用: 結果取得→精算→再学習→Excel
python -m keirin predict       本番用: 発走前レースを予想して仮想購入
python -m keirin report        Excel だけ作り直す
python -m pytest               テスト
```

Windows で毎日自動実行したくなったときのために `windows/` の .bat も残しています（Colab では使いません）。

## ファイル構成

```
keirin_colab.ipynb  Colab 用ノートブック
keirin/
  features.py       設計書の列（データ項目一覧）
  race_grade.py     レースの格の点数表
  model.py          予想方法（手作り7:3 / LightGBM / LightGBM+競走得点）と的中率の評価
  combos.py         1着確率 → 2車複/2車単/3連複の確率
  strategy.py       仮想購入のルール（本命 / 期待値 / 人気1位）
  pipeline.py       取り込み・検証・仮想購入・精算
  report.py         Excel 出力
  db.py             データベース（SQLite）
  sources/          データ取得元（sample=架空, csv, ここにサイト用を追加）
templates/          CSV の見本
tests/              自動テスト
```
